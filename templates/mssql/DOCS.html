connect your database

Your .env is already created in the workspace root — open it and fill in your connection. That's the only setup. The mssql-dba MCP server reads it on launch and validates it, failing fast with a clear message if something's missing.

# authentication — sql (login) or windows (NTLM) DB_AUTH_TYPE=sql   # required DB_HOST=localhost DB_NAME=master # a read-only login, never sa DB_USER=shadow-dba DB_PASSWORD=YourStrongPasswordHere   # common options DB_PORT=1433 ENCRYPT=true # true only for a self-signed certificate (dev) TRUST_SERVER_CERTIFICATE=false

Which auth type?

Set DB_AUTH_TYPE to sql for a SQL Server login (username + password), or windows for Windows / NTLM. Both need DB_USER and DB_PASSWORD — NTLM can't reuse your logged-in session. For an Active Directory account, also set the optional DB_DOMAIN.

Which login?

A read-only login, never sa. The MCP refuses to start with an admin login. Create it once with the setup script (VIEW SERVER STATE, VIEW ANY DEFINITION, and a few msdb reads).

What's required?

DB_HOST, DB_NAME, DB_USER, and DB_PASSWORD are always required. Everything else has a sensible default.

Connection or certificate errors?

Keep ENCRYPT=true. If you hit a TLS / self-signed certificate error on a dev box, set TRUST_SERVER_CERTIFICATE=true. Point DB_PORT at your instance if it isn't on 1433.

Then what?

Run claude in the workspace — your editor's integrated terminal already opens here — and ask it anything. See the common workflows below.

Skills.

Each card shows what to say. Trigger a skill in plain language or with its slash command — either routes to the right playbook. Each one only reads; it hands back a script or findings for you to apply.

instance-risk-audit

Reliability, security and configuration audit — outages first, then patching, alerting, backups, CHECKDB and config risks. Ends with a 0–100 health score.

say run a health check · is the server healthy · are we patched · security audit

performance-audit

Owns every performance question. Firefight mode for “slow right now” (top wait → queries → resource); review mode for a full look at waits, top queries, memory, IO and tempdb.

say why is SQL slow · analyze the performance · what's blocking

exec-plan-analysis

Routes a saved plan to its own subagent (so huge plan XML never floods the chat), then validates every index idea against your live DMVs before you ever see it.

say analyze this execution plan · why is this query slow @plan.xml

index-tuning

Missing, unused, duplicate, fragmented, bad fill factor — consolidated into one ordered script instead of raw DMV dumps.

say tune the indexes · what indexes are missing · fix fragmentation

backup-audit

If the box died now — how much would you lose, how fast could you recover? Checks RPO/RTO, chain integrity, and DR gaps.

say are we backed up · can we restore · what's our RPO

schema-review

Pure advice — it reviews and flags, applying nothing. Catches design anti-patterns: weak PKs, heaps, unindexed or untrusted FKs, wrong types, collation drift, identity columns running out.

say review this table · is this schema ok · why is this table slow to write

Subagents.

A subagent is a separate worker that specializes on a specific task. It runs in its own context so the work never floods your session.

exec-plan-analyst

Deep-reads multi-megabyte plan XML in isolation so it never floods the main chat, then tags index ideas for live validation.

automatically called by the main agent (using the exec-plan-analysis skill) — you don't call it directly. Just ask to analyze the execution plan in the main chat.

FAQ.

Can the agent change my database?

No. It is read-only in three layers: a read-only login (the MCP refuses to start with an admin login), tools that only read (DMVs, catalog views, backups, waits), and a strict check on its own SELECT queries. The login is the real guarantee. The agent hands you a script and you run it.

Where do its numbers come from?

Every conclusion traces to a live MCP tool call. It never invents a value — if a number wasn't read from your server this session, it isn't stated as fact.

Can I customize the agent?

Yes — any skill, subagent, CLAUDE.md, or convention can be edited to fit your needs. See Customize.

How do I trigger a skill?

Say what you want in plain language, or call it by its slash command. Either way the request routes to the right playbook.

Which client do I need?

Claude Code. The workspace is built and tested for it. The skills, system prompt, and MCP config are plain files, so you can adapt them to another agent yourself.
